## 先说清楚 MCSManager 是干什么的

MCSManager（简称 MCSM）是一个开源的、分布式的游戏服务器管理面板，基于 Web，可以在浏览器里管 Minecraft Java 版、基岩版，也支持泰拉瑞亚、饥荒等服务端。它的 GitHub 仓库一直活跃，雨云在游戏云产品里直接集成了这套面板。

它解决的问题很具体：原版服务端只有控制台，改个参数要开 `server.properties`，装插件要拖文件，多开几个服就全靠 screen 和记性。MCSM 把这些搬到网页上——实例列表、控制台日志、文件管理、配置文件编辑都在一个界面里，还支持多用户和资源分配。

所以"MCSManager 开服"这条路线适合两类人：一是完全没碰过 Linux 的服主，二是同时要管好几个实例、懒得每次 SSH 的人。如果你已经习惯命令行、服务器上还有自己的运维脚本，面板对你来说只是可选项。

## 关键前提：机器放在哪

面板只是管理工具，它得跑在一台机器上。用自己电脑开服的方案教程里很多，但三个现实问题绕不开：

1. **公网地址**。家里的宽带通常没有独立公网 IP，朋友连不进来，得再挂一层内网穿透，而穿透工具要么限速、要么免费版地址几小时变一次。
2. **在线率**。你关机、断网、重启路由器，服就没了。朋友约好晚上八点来，你电脑还在装系统。
3. **性能和备份**。Minecraft 1.18 之后的版本对单核性能的胃口比 1.16 时代大得多，旧笔记本开个整合包服，TPS 掉到十几是常态。

这也是为什么绝大多数能长期开下去的服，最后都落在云服务器上。国内做这块的厂商不少，雨云是其中比较专门的一家——2018 年成立，游戏云是它的主线产品之一，官网把"游戏服务器""我的世界服务器""MC 开服"这类需求单独做了一整条产品线。

## 固定计费还是动态计费

这是雨云独有的一个选项，值得单独说。固定计费就是传统月租，一个月多少钱一清二楚。动态计费则是"低价基础月租 + CPU 超额部分按日结算"，CPU 使用率基准值为 20%，低于 20% 不产生额外费用，高于 20% 的部分按电量计费，内存等其他硬件不产生电费。

听起来很美，但有个前提：**Minecraft 生存服的 CPU 占用很少能长期压在 20% 以下**。一旦有人在线，占用就上去了，电量消耗很快。所以经验上的判断是——

- 几个人偶尔开黑、服务器大部分时间关着：动态计费划算。
- 服长期开着、晚上固定有人玩：固定计费更省心，也不会月底看到账单意外。

雨云支持购买后升级降配、切换计费方式、数据备份，所以一开始选低一档、跑起来再升，比一步买高配更合理。

7. **拿到联机地址**。回到雨云的游戏云管理页，在"NAT 端口映射管理"里找到游戏端口对应的那条记录，复制出来（默认内网端口是 25565），这就是你要发给朋友的服务器地址。
8. **给权限**。在 MCSM 控制台输入 `op 你的游戏ID`，回车，你就拿到管理员权限了。

如果服务端核心不在面板的一键列表里（比如某些版本的原版 Forge），就得走纯 Java 环境：把服务端 jar 或压缩包上传到文件管理，再改启动脚本里的内存参数，形如 `java -Xmx4G -jar 服务端文件名.jar nogui`。`-Xmx` 的值建议比机器总内存小一点，留出系统占用。

## 几个新手最常撞上的坑

**Java 版本对不上**。这是"服务器起不来"的第一大原因。一般建议：1.16 及更早用 Java 8，1.17 到 1.19 用 Java 17，1.20 及以上用 Java 21。装错版本，日志里会直接报 UnsupportedClassVersionError。

**内存给太少**。`-Xmx` 开太小，进服几分钟就卡；开太大，系统本身没内存可用，服务端照样崩。4G 内存的机器给服务端 2.5G 到 3G 比较稳。

**压缩包格式**。MCSM 的在线解压只认 ZIP。上传了个 `.tar.gz` 然后纳闷为什么点不动，属于高频事故。

**多开面板时串号**。如果你有多台 MCSM 面板服，从一个切到另一个时记得清一下浏览器缓存，否则登录进去看到的还是上一个账号的实例。

**端口没映射**。面板里服务器跑得好好的，朋友却连不上，先检查是否只给了内网端口、忘了看 NAT 映射那一条。NAT 模式是共享 IP，端口映射必须配置。
